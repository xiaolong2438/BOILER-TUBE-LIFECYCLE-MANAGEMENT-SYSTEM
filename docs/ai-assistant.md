# AI 数据助手 —— 使用说明（本项目版）

> 迁移来源：`D:\employee-growth-map` 的「AI 数据助手」。
> 本项目：锅炉炉管全生命周期管理系统（静态 HTML + 原生 JS + Cloudflare Pages Functions + D1）。
> 接口契约见 [docs/ai-assistant-spec.md](ai-assistant-spec.md)。

## 0. 它是什么

页面右下角新增一个悬浮入口「AI 数据助手」。点开后用一句中文就能完成：

**清洗检查 → 确认导入 → 撤销导入 → 导出 → 查询 → 统计问答 → 单条修改**

默认**完全离线**：不配置任何模型时使用内置规则引擎，不联网、不外发任何数据。
配置模型后可以获得更自然的多轮理解，但**执行动作仍由系统校验后完成**，模型不能直接改数据。

## 1. 怎么用

1. 打开系统，右下角出现「AI」悬浮按钮，点击展开面板。
2. 在底部输入一句话，或点面板上方的快捷指令。
3. 需要文件时点左下角「上传」选 CSV / Excel。
4. 助手先给**清洗报告**（重复行、日期格式、缺失主键、编码范围、炉号冲突等），可一键导出问题明细。
5. 确认无误后点「确认导入」，导入结果与回执都在对话里。

### 示例问法

| 想做的事 | 直接说 |
| --- | --- |
| 清洗表格 | `帮我检查这份 CSV 能不能导入` / `清洗一下这批寿命数据` |
| 导入数据 | `把这些数据导入系统` / `导入寿命事件台账` |
| 撤销导入 | `撤销上次导入` / `撤销刚才的导入` |
| 导出数据 | `导出当前机组的寿命数据` / `把全部数据导出成 Excel` |
| 查询记录 | `查询 1 号炉高过的测厚记录` / `查 1-WW-FR-008-0003-000 的全部记录` |
| 按条件筛选 | `2 号炉水冷壁前墙的事件` / `壁厚小于 6.5 的测厚记录` / `2024 年的更换记录` |
| 超期未检 | `超过 10 年没检查的管段` / `从未检查过的管段` |
| 数据质量 | `现在数据质量怎么样` / `一共有多少条事件` |
| 修改记录 | `把 1-WW-FR-008-0003-000 的最新测厚记录厚度改成 6.8` |
| 查看能力 | `帮助` |

## 2. 能清洗哪些文件

| 数据集 | 识别方式 | 必需列 | 可写库 |
| --- | --- | --- | --- |
| 寿命事件 / 检测记录 | 表头含「管段编码」「日期」等，或文件名含「寿命/事件/管段」 | 日期、管段编码 | 是（含「更换」类行） |
| 受热面材料库 | 表头含「部件名称」「规格型号」「材质」 | 部件名称、规格型号、材质 | 是 |

清洗规则与页面「数据录入」的导入解析**完全同一口径**（所以「清洗能过」基本等于「导入能过」）：

| 检查项 | 级别 | 处理方式 |
| --- | --- | --- |
| 缺日期 / 管段编码（更换行还缺关联新管码） | 错误 | 阻止导入，列出具体行号 |
| 炉号与管段编码首位不一致 | 错误 | 该行不进导入结果（与页面导入的跳过逻辑一致） |
| 数据分类既不是「事件」也不是「更换」 | 警告 | 跳过该行，保留原文提示 |
| 日期无法解析 | 警告 | 能识别就归一为 `YYYY-MM-DD`，否则保留原文 |
| 厚度 / 硬度不是数字 | 警告 | 只提示，行仍保留 |
| 完全重复的业务行 | 警告 | 只保留首行，其余行号全部列出 |
| 编码格式不合规 / 已报废 / 超出台账矩阵 | 警告 | 只提示，不阻断 |
| 多余空列、全空行 | 提示 | 自动丢弃，不影响导入 |

清洗完成后卡片直接给三个动作：**确认导入**、**导出清洗后数据**（CSV）、**导出问题明细**（CSV）。

## 3. 安全设计

1. **预览零写入**：清洗与修改预览阶段不写任何数据。
2. **确认才执行**：导入、修改、撤销都必须点卡片按钮确认；撤销导入还会再弹一次确认。
3. **改完能撤销**：单条修改生效后卡片出现「撤销这次修改」，点一下把原值写回。
4. **只回滚自己**：撤销导入只移除助手自己最近一次导入新增的记录（按写入时间戳精确定位），不影响页面原有导入。
5. **工号式主键保护**：修改管段编码时校验编码格式，并同步修正记录所属机组。
6. **落盘即同步**：写入后调用既有 `saveDB()` / `saveMaterialLibrary()`，本地存储与云端 KV（`/api/storage`）沿用原链路。

## 4. 权限

| 角色 | 来源 | 能做什么 |
| --- | --- | --- |
| 只读 | `?assistantRole=viewer` 或会话角色为 viewer | 清洗、导出、查询、统计、帮助 |
| 编辑 | 已登录的普通账号，或本地离线模式 | 以上全部 + 导入、修改、撤销 |
| 管理员 | 会话角色为 admin | 以上全部 |

角色不足时助手会直接拒绝并说明「该操作需要编辑权限」，不会发起写请求。

## 5. 大模型接入（可选）

默认不需要配置。想让它更"听得懂"，复用总览页已有的「模型接口配置与深度分析」：

1. 打开总览页 → 展开「模型接口配置与深度分析」。
2. 选择服务商预设（DeepSeek / 通义 / Kimi / 智谱 / [OI]），填 Base URL、API Key。
3. 点「识别可用模型」选一个模型，点「保存配置」。
4. 回到助手面板，底部状态会从「规则引擎（离线）」变成模型已配置。

配置在浏览器本地（`boiler_llm_config`），不会进入代码仓库。
面板底部「模型设置」按钮可直接跳到该配置区。

### 模型只负责「听懂」

- 发给模型的只有：**你这句话 + 列名 + 统计数字**；原始数据行永不出浏览器。
- 发送前对 18 位证件号、11 位手机号、邮箱做脱敏替换。
- 模型返回必须是结构化 JSON（意图 + 数据集 + 参数）；工具名与数据集都会再校验一遍。
- 任何故障（超时 9 秒、返回非 JSON、网络错误）都会自动降级为规则解析，并在回复里标注
  「模型调用失败：<原因>（已降级为规则解析）」，不会中断对话。

## 6. 会话历史

面板标题栏「☰」列出最近 20 个会话，可点开继续或删除；「＋」新建会话。
历史只保存**对话文本**，清洗卡片、操作卡片这类执行结果不会回放。
历史存在本浏览器（`boiler_assistant_history`），不跨设备。

## 7. 分层与开发说明

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 领域（纯函数） | `assets/app/assistant-core-v1.js` | 数据集注册、工具目录、意图/查询/编辑解析、清洗规则、统计 |
| UI 层 | `assets/app/assistant-ui-v1.js` | 纯渲染函数 + 面板控制器（只碰 DOM，不碰业务） |
| 接线层 | `assets/app/assistant-v1.js` | 读页面数据、复用既有导入/导出/修改、会话历史、模型增强、门面 |
| 样式 | `assets/app/assistant-v1.css` | `assistant-*` 前缀，只用既有设计令牌，深浅主题自适应 |

接线层对外只暴露一个门面：

```js
window.BTAssistant = {
  mount(), open(), close(), toggle(), isOpen(),
  send(text), handleFile(file), refresh()
}
```

对既有应用的改造保持在最小范围（`assets/app/app-v7.9.js`）：

- `importLifecycleRows(rawRows, options)` / `importMaterialRows(rawRows)`：把 CSV 行处理抽出来共用，口径不变
- `sendLLMMessages(messages, maxTokens, options)` / `callAssistantChatCompletions(messages, maxTokens)`
- `updateEventRecord(ts, field, value)`：单字段修改（带校验与前后值回执）
- `collectAssistantSnapshot()` / `getAssistantRole()`

### 本地校验

```bash

node tests/assistant-wiring.test.mjs      # 接线层：对话主流程、导入、导出、历史

python tests/run-assistant-browser.py    # 真实 Edge 冒烟：开面板/帮助/统计/上传清洗/导入/撤销
```

## 8. 已知边界

- 助手只处理**当前浏览器可见的数据**（localStorage + 云端 KV 同步后的结果），不是服务端全量。
- 单个文件超过 5000 行时助手拒绝处理，请拆分后重试或走页面原导入入口。
- 撤销只保留**最近一次**导入 / 修改。
- 查询结果卡片最多展示 12 条，导出得到的是完整结果。
- 不支持的旧版台账格式（表头无法识别）只会做通用清洗并提示去专用入口导入。
