# AI 数据助手 —— 使用说明（本项目版）

> 迁移来源：`D:\employee-growth-map` 的「AI 数据助手」。
> 本项目：锅炉炉管全生命周期管理系统（静态 HTML + 原生 JS + Cloudflare Pages Functions + D1）。
> 接口契约见 [docs/ai-assistant-spec.md](ai-assistant-spec.md)。

## 0. 它是什么

页面右下角新增一个悬浮入口「AI 数据助手」。点开后用一句中文就能完成：

**清洗检查 → 确认导入 → 撤销导入 → 导出 → 查询 → 统计问答 → 分析出图 → 单条修改**

默认**完全离线**：不配置任何模型时使用内置规则引擎，不联网、不外发任何数据。
配置模型后可以获得更自然的多轮理解，但**执行动作仍由系统校验后完成**，模型不能直接改数据。

## 1. 怎么用

1. 打开系统，右下角出现「AI」悬浮按钮，点击展开面板。
2. 在底部输入一句话，或点面板上方的快捷指令。
3. 需要文件时点左下角「上传」选 CSV / Excel / Word / 图片 / PDF；**多张图片可以一次选中**，也可以直接把文件拖进窗口。
4. 助手先给**清洗报告**（重复行、日期格式、缺失主键、编码范围、炉号冲突、字段映射、疑似错码建议等），可一键导出问题明细。
5. 编辑权限下**干净行自动入库**（无需点按钮），带警告的行留下待确认卡片，点「确认导入」才写入；导入结果与回执都在对话里，且随时可以「撤销导入」。
6. 上传过的图片 / 文件会**留在本会话**（最多 3 个，超出自动淘汰最旧的），可以继续多轮追问与引用，不用重复上传。

## 2. 能清洗哪些文件

### 2.0 智能字段匹配与编码匹配（列名 / 编码不规范也能导）

现场文件很少和模板长得一模一样，助手在清洗时做了三层对齐：

1. **精确别名**：`实测壁厚` → `厚度(mm)`、`管段编号` → `管段编码` 这类内置别名表，秒出。
2. **模糊匹配（本地）**：精确别名没命中时，按「括号单位剥离 + 包含关系 + 编辑距离」兜底——
   `实测壁厚值(mm)` → `厚度(mm)`、`测量日期` → `日期`、`管径(mm)`/`壁厚（mm）` → `管径`/`壁厚`。
   剥掉括号单位后与标准列名完全一致的形态直接命中（覆盖「带单位表头」这一最常见写法）；
   两个标准列得分并列或剥后同形时不映射（宁可不映射也不错误归并），
   未识别列原样保留在结果末尾、不写台账。所有映射都会在清洗报告的「字段智能匹配」卡片里列出来，可人工复核。
3. **模型映射（可选）**：本地没认出的列（或整个表头都不是模板），配置了大模型时会自动发起一次
   「字段映射」请求——模型只看到**列名 + 前两行样例值**（原始数据不出浏览器），返回列名映射与数据集类型；
   结果按文件名缓存，同一份文件「再次清洗」不会重复调用模型。模型失败/不可用则安静降级为本地结果，不会中断导入。

匹配完成后，清洗结果会**按模板列序重排**（缺失的模板列补空列占位）——页面导入是按列位置取数的，
这一步保证列顺序不同的文件也不会错位入库。

编码同样会智能匹配：管段编码不在台账（已有记录 + 台账矩阵展开）中时，自动找**最相似的真实编码**给建议
（如 `1G-SLB-WB-F000-R030-Q001 ≈ 1G-SLB-WB-F000-R003-Q001，相似度 93%`，只看同机组同系统的候选），
标记为「编码未在台账中找到」警告；更换产生的 `-R1` 新管码剥掉后缀后比对，不会误报。
矩阵外的编码若与真实编码高度相似，也会在「超出台账矩阵范围」的样例里附上近似码。

**计数方向自动归一**：现场可以就近从任意一端数管（炉左/炉右、炉前/炉后、上/下），方向字母与序号互为镜像
（`L025 ≡ R168`，即总数+1−n）。台账矩阵展开只认规范方向（dirs/posLetters 首位），清洗时把「反方向但矩阵合法」的
编码**无损换算成同一物理位置的规范编码**——管号方向（L↔R、F↔B、U↔D）、排/小屏号方位、检修空间与 Q 流水号
（原样保留宽度）一并处理，燃烧器区域无方向段不参与。换算结果进「编码计数方向已归一」警告行（人工确认后入库），
归一明细写入清洗报告，同一记录的两种数法在归一后自动去重，台账身份唯一、历史不断裂。
镜像后越界的编码不归一，仍走既有的 out_of_range / 笔误建议路径。
页面「数据录入」的 Excel/CSV 批量导入与手工录入/更换登记**同一口径归一**（导入结果会提示「方向归一 N 条」），
不会出现「助手导入已归一、页面直录仍是反方向」的分叉。

数据集类型识别同样支持文件名兜底：表头不是标准模板时，文件名包含「寿命/事件/检测/测厚/管段/炉管/记录」
按事件台账处理，包含「材料/备件/库存/受热面」按材料库处理（与数据集注册表 keywords 同源，避免文档与实现漂移）。

清洗规则与页面「数据录入」的导入解析**完全同一口径**（所以「清洗能过」基本等于「导入能过」）：

| 检查项 | 级别 | 处理方式 |
| --- | --- | --- |
| 缺日期 / 管段编码（更换行还缺关联新管码） | 错误 | 阻止导入，列出具体行号 |
| 炉号与管段编码首位不一致 | 错误 | 该行不进导入结果（与页面导入的跳过逻辑一致） |
| 数据分类既不是「事件」也不是「更换」 | 警告 | 跳过该行，保留原文提示 |
| 日期无法解析 | 警告 | 能识别就归一为 `YYYY-MM-DD`，否则保留原文 |
| 厚度 / 硬度不是数字 | 警告 | 只提示，行仍保留 |
| 完全重复的业务行 | 警告 | 只保留首行，其余行号全部列出 |
| 编码格式不合规 / 已报废 / 超出台账矩阵 | 警告 | 只提示，不阻断 |
| 多余空列、全空行 | 提示 | 自动丢弃，不影响导入 |

清洗完成后卡片直接给三个动作：**确认导入**、**导出清洗后数据**（CSV）、**导出问题明细**（CSV）。

### 2.1 图片 / PDF / Word 识别（拍照记录、检验报告、Word 台账）

除了 CSV / Excel，还可以直接把**照片、截图、PDF 报告、Word 文档**拖进助手窗口。识别结果会转换成与 CSV 完全一致的表头 + 数据行网格，
再走上面**同一套清洗规则与导入链路**（清洗报告 → 确认导入 → 撤销），不另开写入通道。

| 来源 | 处理方式 | 说明 |
| --- | --- | --- |
| 图片 png / jpg / jpeg / webp | 本地压缩到长边 1568px → 视觉大模型 → 表格 | 支持一次选/拖多张（上限 8 张），逐张**串行**识别后合并 |
| PDF（有文本层） | pdf.js 提取文本 → 行列聚类成表 | 扫描件（纯图片型）PDF 请改用截图/拍照 |
| PDF（文本层不成表） | 文本交大模型兜底提取 | 需要已配置模型 |
| Word .docx（含表格） | 零依赖 ZIP 解压 + OOXML 表格提取（浏览器原生 DecompressionStream） | 多表自动合并、gridSpan 补空列对齐；**本地即可解析，不需要模型** |
| Word .docx（无表格） | 正文文字交大模型兜底提取 | 需要已配置模型 |
| Word 旧版 .doc | 不支持 | 二进制格式无法直接解析，请「另存为」.docx 或截图后用图片识别 |

从"识别"到"可导入"，提炼层做了四件事：

1. **多图合并**：表头按首次出现顺序取并集、缺失列补空；完全重复的数据行只保留第一行。备注里给出"合并 n 份 / 去重 n 行 / 丢弃空行"统计。
2. **字段规范化（无损）**：全角转半角、去零宽字符与首尾空白；日期列 `2024年1月5日` / `2024.1.5` / `20240105` → `2024-01-05`；
   厚度/壁厚/硬度/库存列 `6.5mm` → `6.5`、`183HB` → `183`、`1,234` → `1234`；编码列去掉所有空白（不改大小写）。
   **识别不了的一律保留原文**（`6.5~7.0`、`见附页`、`2024年13月45日`、`2023年2月29日` 都不动），
   交给清洗层照常报 `invalid_date` / `invalid_number` 警告 —— 不臆造数值，也不丢数据。
3. **模型输出修复**：模型返回的不是合法 JSON 时，自动把原始输出（截断 2000 字符）与解析错误回传，要求"只输出 JSON"再试一次（**最多一次**）；
   仍然失败才报错，并在错误信息里附上原始输出片段，方便对着截图排查。
4. **不确定单元格**：提示词要求模型对拿不准的单元格给出坐标（`uncertain`）。这些单元格**置空**并在备注里提示
   "n 个单元格识别不确定已置空，请人工核对"。宁可缺值（缺值会被清洗标成警告行、由人工确认），也不让错误数值直接入库。

单张图片失败不会拖垮整批：备注里会写明"成功 n 张、失败 m 张（文件名：原因）"；**全部失败**或识别不出表格时才中止并说明原因，不会进入清洗。

### 2.2 多轮对话与会话附件

上传不是"一锤子买卖"：图片 / PDF / 表格上传后会登记为**本会话的附件**，消息区上方的附件条会一直显示它们
（序号、名称、类型、行数），当前生效的那条高亮。之后的每一轮对话都可以继续引用：

| 想做的事 | 直接说 | 说明 |
| --- | --- | --- |
| 追问图片内容 | `这张图里有几个测点？`、`图上的编号是什么？`、`照片里的日期是多少？` | 会把**原图 + 最近几轮对话**一起发给视觉模型，回答以「【基于图片 名称】」前缀呈现，**不写库** |
| 指代切换 | `第二张图呢？` / `看第一个附件` / `最后一张图` | 支持"这个/该/刚才的/最新的 + 表|文件|附件|图|图片|照片|PDF"、"第 N 个/份/张"（阿拉伯与中文数字）、"第一张/最后一张/上一个" |
| 问附件本身 | `有几个附件`、`这个表多少行`、`有哪些列` | 离线可答（不调用模型） |
| 再次导入 | `导入` | 若当前附件已经导入过，助手**不会直接重复写库**，而是回执"该附件已于 <时间> 导入过（N 行）"并给出「再次导入」按钮，点一下才重新走清洗与确认 |
| 清理 | 附件条上的 ✕ / 新会话 | 新开会话会清空附件 |

设计要点：

- **多轮上下文**：判断意图时会带上**最近 6 轮对话**（脱敏、单条截断 200 字）与附件清单，因此"它""刚才那个""第二张"这类指代能被理解。
- **图片追问优先于规则**：命中图片指代 + 疑问/请求语气时直接走视觉问答，不会静默降级成"答非所问"的库内查询；
  未配置视觉模型、原图已释放、或当前附件不是图片时，都会给出明确中文提示。
- **再次导入保护**：附件上的 `importedAt` 让"重复导入"必须显式确认，避免一句"导入"把同一批数据写两遍。
- **附件上限 3 条**（FIFO 淘汰最旧的），避免一次拖入过多图片把模型额度与内存耗光。
- **持久化只存摘要**：会话历史里保存的是附件的名称/类型/行数/备注；**明细行与原图只存在内存里**。
  重新打开旧会话时，附件仍可查看行数与列名，但不能再次清洗/导入，图片追问会提示"请重新上传"。

## 3. 安全设计

1. **预览零写入**：清洗与修改预览阶段不写任何数据。
2. **确认才执行**：导入、修改、撤销都必须点卡片按钮确认；撤销导入还会再弹一次确认。
3. **改完能撤销**：单条修改生效后卡片出现「撤销这次修改」，点一下把原值写回。
4. **只回滚自己**：撤销导入只移除助手自己最近一次导入新增的记录（按写入时间戳精确定位），不影响页面原有导入。
5. **工号式主键保护**：修改管段编码时校验编码格式，并同步修正记录所属机组。
6. **落盘即同步**：写入后调用既有 `saveDB()` / `saveMaterialLibrary()`，本地存储与云端 KV（`/api/storage`）沿用原链路。
7. **写入即留痕**：导入、修改、撤销、材料库变更都会写入左侧「维护记录」，可在那里看到字段级前后值与来源（AI 助手 / 手工 / 文件导入）。详见 [maintenance-log.md](maintenance-log.md)。
8. **图片识别会把图片发给模型**：只有在"你主动上传图片 / PDF + 已配置模型"时才会外发图片本身（PDF 走文本层时不外发文件）；
   不配置模型时不会有任何图片离开浏览器。识别结果落库前仍然要过本地清洗与人工确认。
9. **图片追问同样外发图片与最近几轮对话文本**：只在你主动对图片附件提问、且已配置模型时发生；
   对话文本发送前会做脱敏（证件号/手机号/邮箱），追问回答只作为文字呈现，**不会写入台账**，更不会替你做导入决定。

## 4. 权限

| 角色 | 来源 | 能做什么 |
| --- | --- | --- |
| 只读 | `?assistantRole=viewer` 或会话角色为 viewer | 清洗、导出、查询、统计、分析、帮助 |
| 编辑 | 已登录的普通账号，或本地离线模式 | 以上全部 + 导入、修改、撤销 |

角色不足时助手会直接拒绝并说明「该操作需要编辑权限」，不会发起写请求。

## 5. 大模型接入（可选）

默认不需要配置。配置只存一处（`boiler_llm_config`），助手、深度分析、单管分析共用；
面板状态会显示「已载入配置 / 还缺 API Key / 未配置」三种情况。

想让它更"听得懂"，复用总览页已有的「模型接口配置与深度分析」：

1. 打开总览页 → 展开「模型接口配置与深度分析」。
2. 选择服务商预设（DeepSeek / 通义 / Kimi / 智谱 / [OI]），填 Base URL、API Key。
3. 点「识别可用模型」选一个模型，点「保存配置」。
4. 回到助手面板，底部状态会从「规则引擎（离线）」变成模型已配置。

配置在浏览器本地（`boiler_llm_config`），不会进入代码仓库。

**什么时候会让模型判意图**：只有规则引擎置信度低于 0.6，或完全没听懂时才调用模型；
「帮助」「导出」这类明确指令走规则，不额外等一次网络往返。文件流程（待导入/待清洗）中不会打断去问模型。
面板底部「模型设置」按钮可直接跳到该配置区。

### 模型只负责「听懂」

- 发给模型的只有：**你这句话 + 列名 + 统计数字**；原始数据行永不出浏览器。
- 发送前对 18 位证件号、11 位手机号、邮箱做脱敏替换。
- 模型返回必须是结构化 JSON（意图 + 数据集 + 参数）；工具名与数据集都会再校验一遍。
- 任何故障（超时 9 秒、返回非 JSON、网络错误）都会自动降级为规则解析，并在回复里标注
  「模型调用失败：<原因>（已降级为规则解析）」，不会中断对话。

## 6. 数据分析与可视化

一句中文就能出图，不需要先选数据集或配图表。助手会自己判断「看什么维度、用什么图、结论是什么」。

| 分析类型 | 怎么问 | 出什么图 | 看什么 |
| --- | --- | --- | --- |
| 趋势 | `近两年壁厚趋势`、`按年统计更换次数趋势` | 折线（均值 + 最低值） | 壁厚是在缓慢减薄还是突变；哪一期是拐点 |
| 分布 | `壁厚分布`、`各受热面事件数分布` | 柱状（自动分箱）/ 环形 | 数据集中在哪个区间、有没有离群尾巴 |
| 排行 | `受热面事件数排行`、`最薄壁厚前 5` | 横向条形 | 哪些受热面/管段最该先看 |
| 对比 | `1 号和 2 号炉壁厚对比` | 分组柱状 | 两台机组差异有多大 |
| 相关性 | `壁厚和硬度相关性` | 散点 + 皮尔逊 r | 减薄是否伴随组织劣化 |
| 异常识别 | `壁厚异常记录` | 散点 + IQR 下界 | 哪些记录低于整体下界或名义壁厚 80% |
| 单管剖面 | `1G-SLB-WB-F000-R003-Q001 壁厚变化曲线` | 折线 + 80% 阈值线 | 这根管子还剩多少裕量 |
| 综合画像 | `数据整体画像` | 环形 + 指标组 | 一次看全：事件量、管段数、更换、超期、预警 |

### 有没有大模型，差别在哪

| 场景 | 图表 | 结论 | 卡片标识 |
| --- | --- | --- | --- |
| 未配置模型（默认） | 规则按问法选图，秒出 | 规则模板结论（带数据依据） | 无徽标 |
| 已配置模型 | 模型可建议更合适的口径，本地重算后出图 | **模型写结论与建议**，每条必须引用给定向数据 | 紫色「模型解读」徽标 + 建议块 |

启用方式就是总览页的「模型接口配置」——不用额外开关。分析会**先秒出规则版**，再异步升级成 AI 版；
模型超时或返回不可用时保留规则结论，并在卡片底部注明原因，不会卡住对话。

防编造的做法：只有**聚合后的指标和序列**会发给模型（原始行、明细表、管段编码都不出浏览器）；
模型写的每条结论必须包含一个给定向数据里出现过的数字，否则整条被过滤，卡片会注明「有 N 条结论被过滤」。

每张卡片固定包含四块：

1. **指标**：4~6 个关键数字（样本数、均值、最低值、峰值期等），风险值带颜色。
2. **图表**：纯 SVG 绘制，深浅主题自动跟随，不依赖任何图表库。
3. **结论**：3~5 条中文判断，每条都带数据依据（不是空话），例如
   「平均壁厚从 7.42mm 变为 6.91mm，累计下降 0.51mm（-6.9%）」「最集中区间是 6.9~7.1，占 31.0%」。
4. **明细**：前 6 行预览 + 「导出分析明细」，导出的 CSV 是完整结果。

口径说明：

- 分析与「查询」共用同一套过滤条件（机组 / 受热面 / 类型 / 日期 / 壁厚区间），所以「1 号炉水冷壁近两年壁厚趋势」会四重收窄后再算。
- 说「1 号和 2 号炉对比」时会自动放开机组条件，否则只会剩一台机组。
- 名义壁厚从规格列的「Φ63.5×7.5」里取，用来算减薄率；规格没写的记录只参与均值，不算减薄率。
- 折线图按数据量级取纵轴，不从 0 起算 —— 7.4→6.9 这种变化能看清，不会被压成一条平线。
- 样本不够时会直接说明（例如「同时有壁厚和硬度的记录只有 2 条，至少需要 3 条才能算相关性」），不会硬给一个结论。
- 带「模型解读」徽标的结论由对话模型生成，属于**辅助判断**；涉检修决策仍需人工复核，卡片上的数字与图表始终来自本地计算。
- 总览页「深度分析」和管段综合分析的报告也会做**数值审计**：报告中出现本地数据里没有的数值（如 5.55mm、168HB）时，
  会在报告上方提示具体数值，但不改写模型原文；纯数量（如"相邻 12 根"）不判定，避免误报。

## 9. 已知边界

- 助手只处理**当前浏览器可见的数据**（localStorage + 云端 KV 同步后的结果），不是服务端全量。
- 单个文件超过 5000 行时助手拒绝处理，请拆分后重试或走页面原导入入口。
- 撤销只保留**最近一次**导入 / 修改。
- 查询结果卡片最多展示 12 条，导出得到的是完整结果。
- 不支持的旧版台账格式（表头无法识别）只会做通用清洗并提示去专用入口导入。
- 分析结果只统计**当前浏览器可见的数据**；图表是内联 SVG（矢量、跟随深浅主题），暂不支持导出图片，但明细可导出 CSV。
- **图片识别依赖视觉大模型**：未配置模型时上传图片会直接提示去「模型接口配置」配置，不会退化成离线 OCR。
- 一次最多 8 张图片；多文件里只要有一个不是图片，就按"混合类型"提示，不会部分识别。
- PDF **文本层**直接提取的表格不做字段规范化（只走通用清洗），只有图片与大模型兜底提取的路径做规范化；
  扫描件 PDF 无法识别文字，请截图/拍照后按图片上传。
- 多图合并会丢弃**完全重复**的数据行（与清洗层"重复行只留首行"口径一致），备注里会写明丢弃行数。
- **Word 只支持 .docx**：旧版 .doc 是二进制格式无法解析，助手会提示另存为 .docx 或截图后用图片识别；
  含表格的 .docx 本地即可提取（不需要模型），无表格的 .docx 需要配置模型做文本兜底。
- **模糊表头匹配按列名相似度判断**：映射结果会在清洗报告里列出，导入前请抽查数值列是否对位；
  数据集类型检测仍只认精确别名，整个表头都不是模板时要靠模型映射兜底（需配置模型），否则按通用清洗提示处理。
- **编码相似建议只在高度相似时给出**（同机组同系统、相似度 ≥82%），相似度低可能是合法新管码，不会误报；
  更换产生的 -R1 后缀新管码会先剥后缀再比对。
- 会话附件上限 **3 条**，第 4 次上传会淘汰最旧的；附件明细行与原图**只存在当前会话内存中**，
  刷新页面或切换到旧会话后只剩摘要（行数/列名/备注），需重新上传才能再次识别或追问图片。
- 图片追问依赖视觉模型；追问回答是**辅助理解**，不写台账，也不代表已完成导入。
- "再次导入"必须先完成一轮导入（点过「确认导入」）；若上一次清洗结果还挂着未确认，说"导入"仍然是导入预览。
