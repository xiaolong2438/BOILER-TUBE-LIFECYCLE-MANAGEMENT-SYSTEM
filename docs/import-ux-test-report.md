## 三、验收详情

### 3.1 识别和分类

- **数据集识别三级兜底**：标准表头精确别名命中 → 别名表头靠文件名关键词 → 都不中判 unknown。
  实测：「现场检测记录-乱序列.csv」（表头全部为现场叫法）靠文件名正确判为「寿命事件/检测记录」；
  材料库别名表头靠文件名判为「受热面材料库」；供应商清单判 unknown 且**绝不误写库**（端到端验证无写入、无导入按钮）。
- **事件类型现场叫法归一（9 组）**：探伤→无损检测、金相→金相分析、爆管更换→报废更换、壁厚测量→测厚、投运→安装投运等全部正确。
- **数据分类口径**：`event`/`Replacement`（英文大小写）正确归一；非法值行跳过并明确提示，不阻断其余行。
- **防误判设计有效**：模糊命中列（如「设备编码」）不参与数据集分类；两个标准列同分时不映射。

### 3.2 模糊定位

- **表头模糊匹配（10 列现场叫法）**：`实测壁厚值(mm)→厚度(mm)`、`布氏硬度值→硬度(HB)`、`设备编码→管段编码`、
  `钢管规格→规格`、`材质牌号→材质`、`结论备注→详细描述/结论` 等全部命中；映射在清洗报告「字段智能匹配」卡片
  逐列可视化（原始列名 + 目标列名 + 匹配来源），支持人工复核。
- **歧义保护**：「编码备注」同时含「编码」与「备注」→ 得分并列不映射，宁缺勿错；「天气」「供应商电话」返回 none 原样保留。
- **模型映射**：`headerMap` 优先级最高且只认合法目标列，非法目标自动忽略。
- **列序归一**：乱序文件清洗后按模板列序重排、缺失模板列补空占位——**逐列对位断言全部通过**（导入准确性的根基）。
- **编码模糊定位**：`1-WW-FR-080-0003-000`（矩阵外笔误）给出近似建议 + 相似度百分比；建议只在同机组同系统内
  找（跨系统候选被过滤）；相似度 <82% 不误报（可能是合法新管码）；更换产生的 `-R1` 新管码剥后缀比对不误报。

### 3.3 AI 辅助清洗与导入（端到端，真实浏览器）

乱序别名 CSV（5 行：3 干净 + 1 笔误编码 + 1 缺管码）上传后：

1. **3 行干净数据免按钮自动入库**（0 秒等待，无需点击）；
2. 笔误编码行进入**待确认卡片**，卡片给出 `近似：1-WW-FR-001-0003-000（相似度 93%）`；
3. 缺管码行**错误阻断**并说明行号；
4. 「确认导入」→ 写入 +1；「撤销这次导入」→ 精确回滚，台账恢复原状；
5. 对话流全程可见：字段智能匹配明细、警告原因、导入回执（新增事件 N 条）。

Word `.docx` 台账（OOXML 表格）走完全相同链路：本地零依赖提取 → 合并去重留痕 → 识别为事件台账 →
干净行自动入库 2 行 → 无效日期行（2025-02-30）待确认 → 确认 → 撤销。**Word 与 CSV 同一口径**。

材料库别名 CSV 同样验证通过：自动入库 + 确认导入 + 撤销，`材质牌号` 等模糊映射正确。

### 3.4 清洗准确性（逐行核对）

- 日期五格式归一：`2024年3月5日` / `2024/4/8` / `2024.4.15` / `20240415` → `YYYY-MM-DD`；
  `2025-02-30`、`2024年13月45日` **保留原文并警告，不臆造**；
- 脏值不丢：`6.5~7.0` 区间厚度原文保留 + 警告 + 人工确认，不猜数值；
- 重复行只保留首行（`droppedRows=[5]`、`keptRows=[1]`）；空行自动丢弃；BOM 表头自动去除并提示；
- 缺日期/管码行、更换缺关联新管码行：错误级阻断并列行号；炉号与编码首位不一致：阻断；
- **写库内容抽查**：入库记录的 `code`/`date`/`thickness` 与源文件逐字段一致（端到端）。

### 3.5 便捷性与性能

- 2000 行脏数据清洗 **9ms**（<3s 断言）；2001 行报告完整（总数/存活/错误/警告）；
- 单文件 5000 行上限、一次最多 8 张图片等边界常量在位（超限给出拆分指引，不崩溃）；
- 助手与页面原导入共用 `importLifecycleRows`（同一口径，合同断言通过）；
- 角色控制：viewer 不出现导入动作（`manualMode` 兜底整表确认流程）。

## 四、发现问题清单

### F1（P2·建议修复）材料库带单位表头识别失败：`管径(mm)` / `壁厚(mm)` → 未识别

- **复现**：`fuzzyMatchHeader('material_library', '管径(mm)')` → null；清洗后该列原样保留在结果末尾，数值不入库字段。
- **根因**：精确别名层用 `normalizeText`（不剥括号单位），`管径(mm)` ≠ 别名 `管径`；模糊层的包含匹配又把
  「剥括号后与别名相等」的候选显式跳过（`assistant-core-v1.js` fuzzyMatchHeader 中 `if (aliasKey === headerKey) return;`）。
  两层恰好互相错开，最常见的真实表头形态两头落空。
- **影响**：数据安全（不写错列），但材料库「管径/壁厚」最常以带单位形式出现，现场文件需要手工改名才能入库完整字段。
- **建议**：模糊层对「剥括号后相等」的别名直接命中（它正是精确层漏掉的形态）。

### F2（P3·建议改进）跨层级不比分：包含 0.5 分压过编辑距离 0.75 分

- **复现**：`事件类别` / `检测类别` → 「数据分类」（包含「类别」，0.5），而语义更近的「事件类型」编辑距离 0.75 未参与比较。
- **影响**：若现场文件用「事件类别」表示测厚/金相类型，会被静默映射到「数据分类」，导致这些行被当成分类列解析
  （值不是事件/更换而整行跳过）。属低概率误映射，映射卡片可见可人工纠正。
- **建议**：两级各算分后取全局最高分，同分再防歧义（现有并列保护保留）。

### F3（P3·文档-实现不一致）文件名分类正则缺关键词

- **复现（端到端实测）**：文件名 `现场测厚记录-乱序.csv` 识别失败落入通用清洗；改名含「检测」即恢复。
- **根因**：数据集注册表 `keywords` 声明了 `测厚/炉管/记录`，但 `resolveDatasetType` 实际正则只有
  `寿命|事件|检测|event|管段|tube`（events）——文档能力表与实现不同步。
- **建议**：正则与 keywords 对齐（一行改动），或在文档中收敛承诺。

### F4（观察·已有安全网）相似码建议可能指向"合法但非预期"编码

- **复现**：矩阵展开后候选密集，`1-WW-FR-080-0003-000` 的近似建议是 `1-WW-FR-010-0003-000`（93%），
  而非直觉上的 `008-0003`（90%）——算法无法判断用户敲错的是屏号还是管序。
- **缓解**：该行只进「待确认」，人工核对后才入库；风险可控。
- **建议（可选）**：对仅数字互换（换位/相邻数字）的候选加权排序，把同屏或同管候选排前。

### F5（观察·行为偏保守）重复行检查把"被保留的首行"也列入行号

- 重复组的保留首行因此进入「待确认」而非自动入库（规则：出现在任一警告行号 → 待确认）。
  保守、合理（提示"确认是否有重复录入"），但与"干净行自动入库"的直觉略有出入，现场大批量文件会多几行待确认。
  如需优化：分流时排除 `duplicate_rows.keptRows`。

### F6（观察·覆盖边界）XLSX 助手路径依赖 CDN SheetJS

- 离线/无网环境（CI 无头浏览器剥离外链）无法端到端驱动真实 XLSX 解析。本次做了：openpyxl 生成 + 读回校验
  （真实 Excel 可读）、ZIP/OOXML 结构断言、`parseXlsxRows` 契约依赖 SheetJS 的路径审查。建议后续在 CI 引入
  本地 vendored SheetJS 或无头浏览器放行本地资源，以补齐真实 XLSX 端到端。

### F7（P2·已修复）未识别数据集把「保留行数」显示成「可导入」，容易被误认为已入库

- **现象**：上传无关表格（如供应商清单）后，清洗卡片指标显示「可导入 2」，对话文案写「已检查 2 行数据（可导入 2 行）」，
  而实际结论是 `importable=false`、只做通用清洗、不写库。用户会误以为数据已经进来了。
- **根因**：`cleanRows` 在 unknown 分支里仍统计 `summary.cleanRows`（通用清洗保留行数），而卡片与文案直接把它当可导入行数展示。
- **修复**：
  - `assistant-ui-v1.js`：`datasetType === 'unknown'` 时「可导入」指标显示 `—`；
  - `assistant-v1.js`：`describeCleaning` 对 unknown 改说「通用清洗后保留 N 行，不导入」。
- **验证**：新增 4 条断言——UI 卡片占位符与不误伤已识别数据集（`assistant-ui.test.mjs` 2 项）、
  接线层上传供应商清单后文案与按钮（`assistant-wiring.test.mjs` 1 项）、端到端真实浏览器卡片与对话文案（`import-ux-browser-runtime.js`）。
- **三重阻断未变**：不自动入库、不出现确认导入按钮、手打「导入」被 `pendingCleaningImportable()` 拒绝。
